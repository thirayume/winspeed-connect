# คู่มือระบบซิงค์ข้ามฐานข้อมูล (Cross-Database Sync)
<!-- เอกสารส่งมอบและแนวปฏิบัติสำหรับ IT Administrator: Sale-App World Fertilizer -->

## 1. วัตถุประสงค์และการทำงานของระบบ (Purpose & Architecture)

ระบบ **Cross-Database Sync** (ซิงค์ฐานข้อมูล) ในหน้า **สถานะระบบ (Observability / Ops Console)** ได้รับการออกแบบมาเพื่อให้ผู้ดูแลระบบ (ADMIN) สามารถตรวจสอบความแตกต่าง (Diff / Audit) และถ่ายโอนข้อมูลโครงสร้างหลัก (Master Data & System Configurations) ระหว่างฐานข้อมูลต้นทาง (Source Database) และฐานข้อมูลปลายทาง (Target Database) ได้อย่างปลอดภัย

### ฟังก์ชันหลักของระบบ:
1. **Schema & Migration Audit**: ตรวจสอบสถานะของตาราง `wf.*` และประวัติ migration ว่าปลายทางตามทันต้นทางหรือไม่
2. **User & Org Sync**: ซิงค์รายชื่อผู้ใช้งาน (`wf.AppUser`), ตำแหน่งงาน (`wf.OrgPosition`), และบทบาทสิทธิ์ (`wf.RoleProfile`, `wf.RolePermission`)
3. **Master Data Alignment**: ซิงค์ตารางสินค้า (`dbo.EMGood`), ลูกค้า (`dbo.ARCustomer`), และตารางราคา (`wf.PriceBook`, `dbo.EMSetPriceHD`)
4. **App Settings Consistency**: ซิงค์นโยบายค่าคงที่ของระบบ (`wf.SystemSettings`, `wf.ApprovalPolicy`) เพื่อให้นโยบายตรงกันทุกบริษัทในเครือ

## 2. เรายังจำเป็นต้องใช้หรือไม่? (Is It Still Necessary?)

> **คำตอบ**: **ยังจำเป็นต้องมีและคงไว้ในระบบ แต่จำกัดการใช้งานเฉพาะเหตุการณ์ด้านโครงสร้างพื้นฐาน (Infrastructure & Operations)** โดยไม่ได้ใช้ในงานขายประจำวัน (Daily Sales Routine)

### สรุปความจำเป็นตามบริบทงาน:
- **งานขายประจำวัน (Daily Sales)**: **ไม่ต้องใช้** — การรับส่งข้อมูลประจำวันระหว่าง Sale-App และ WinSpeed (เช่น ใบจอง SO 103, ใบสั่งขาย 104, ตั๋วส่งของ 107/116, เครื่องชั่ง) ทำงานอัตโนมัติผ่าน Background Polling, WinSpeed SPs, และ Transaction Listeners ตลอดเวลาอยู่แล้ว
- **งานปฏิบัติการ IT และผู้ดูแลระบบ (IT Operations)**: **จำเป็นต้องใช้** เมื่อเกิดสถานการณ์ตามข้อ 3 ด้านล่าง

## 3. ใช้เมื่อใด? (When to Use)

| ลำดับ | สถานการณ์ที่ต้องใช้งาน | รายละเอียดและเหตุผล |
| :---: | :--------------------- | :------------------ |
| 1 | **เริ่มต้นติดตั้งฐานข้อมูลบริษัทใหม่ (Onboarding New Company DB)** | เมื่อบริษัทเปิดใช้งานฐานข้อมูลบริษัทใหม่ในเครือ (เช่น `dbwins_worldfert2`) และต้องการคัดลอก Master Data, โครงสร้างสิทธิ์, และ App Settings จาก `dbwins_worldfert` ต้นแบบ โดยไม่ต้องรันสคริปต์ manual ทีละตาราง |
| 2 | **กู้คืนระบบ WinSpeed (Disaster Recovery / Database Restore)** | เมื่อเซิร์ฟเวอร์ WinSpeed มีปัญหาและทีม IT ต้อง Restore ฐานข้อมูลจากไฟล์ `.bak` เก่า ทำให้ข้อมูลใน `wf.*` หรือผู้ใช้งานที่เคยตั้งค่าไว้บน Sale-App สูญหายไป การรัน Sync จะช่วยดึงการตั้งค่าจากระบบสำรองกลับมาได้อย่างรวดเร็ว |
| 3 | **ปรับตั้งค่าสภาพแวดล้อมทดสอบ (UAT Environment Refresh)** | เมื่อมีการ Clone ฐานข้อมูล Production (`dbwins_worldfert`) ลงมาเป็น UAT (`dbwins_worldfert9_uat`) เพื่อทดสอบฟีเจอร์ใหม่ การใช้หน้านี้ช่วยตรวจสอบความสอดคล้องของ Schema และพารามิเตอร์ |
| 4 | **ตรวจสอบความเบี่ยงเบนของนโยบาย (Policy Drift Audit)** | ตรวจสอบว่านโยบายการอนุมัติ (`ApprovalPolicy`) หรือตารางราคากลางระหว่าง 2 ฐานข้อมูลตรงกันหรือไม่ |

## 4. วิธีการใช้งานทีละขั้นตอน (How to Use — Step-by-Step)

### ข้อควรระวังก่อนเริ่ม:
- ผู้ใช้งานต้องมีสิทธิ์ **ADMIN** เท่านั้น
- ตรวจสอบว่าเซิร์ฟเวอร์เป้าหมายเปิดให้เชื่อมต่อ และระบุ connection string ใน `backend/.env` ครบถ้วน
- ระบบมีระบบความปลอดภัย **Dry-Run (ตรวจสอบความแตกต่างก่อน)** เสมอ ห้ามข้ามขั้นตอนนี้

### ขั้นตอนการดำเนินการ:
1. เข้าสู่ระบบด้วยสิทธิ์ **ADMIN**
2. ไปที่เมนู **สถานะระบบ** (Observability / Ops) ในแถบเมนูซ้าย
3. เลือกแท็บ **ซิงค์ฐานข้อมูล (Cross-Database Sync)**
4. **เลือกฐานข้อมูล**:
   - **ฐานข้อมูลต้นทาง (Source DB)**: เลือกฐานข้อมูลแม่แบบ เช่น `dbwins_worldfert` (Production)
   - **ฐานข้อมูลปลายทาง (Target DB)**: เลือกฐานข้อมูลที่ต้องการซิงค์ เช่น `dbwins_worldfert2` หรือ `dbwins_worldfert9_uat`
5. **ขั้นตอนที่ 1: ตรวจสอบความแตกต่าง (Audit / Dry-Run)**:
   - กดปุ่ม **"ตรวจความแตกต่าง (Diff / Dry-Run)"**
   - ระบบจะเปรียบเทียบ Schema, ตารางผู้ใช้, ตารางสินค้า, และนโยบาย แล้วแสดงสรุปความแตกต่าง (เช่น มีผู้ใช้ใหม่ 2 คน, ตารางราคาเวอร์ชันต่างกัน 1 ชุด)
6. **ขั้นตอนที่ 2: ดำเนินการซิงค์ (Execute Sync)**:
   - ตรวจทานรายการที่จะดำเนินการ
   - กดปุ่ม **"ยืนยันการซิงค์ (Execute Sync)"**
   - ระบบจะทำ Snapshot สำรองจุดคืนสภาพ จากนั้นส่งคำสั่งซิงค์แบบ Transactional หากมีข้อผิดพลาดระบบจะ Rollback อัตโนมัติ
7. **ขั้นตอนที่ 3: ตรวจสอบผลลัพธ์ (Verify)**:
   - ระบบจะแสดง Log ผลการรัน `SUCCESS: Synced X records`
   - ตรวจสอบในหน้าจอ Master Data หรือ App Settings ของฐานข้อมูลปลายทางเพื่อยืนยันความถูกต้อง

## 5. การจำกัดสิทธิ์และความปลอดภัย (Security & Safeguards)
1. **Idempotent Execution**: คำสั่งซิงค์ทั้งหมดถูกเขียนให้ปลอดภัย รันซ้ำได้โดยไม่สร้างข้อมูลซ้ำซ้อน
2. **No Data Loss on WinSpeed Core Tables**: ระบบจะไม่ลบหรือแก้ไขข้อมูลใบสั่งขาย (SOHD/SOIT), ข้อมูลบัญชีลูกหนี้ หรือประวัติทางการเงินของ WinSpeed เด็ดขาด
3. **Audit Logged**: ทุกการคลิกและการซิงค์ข้ามฐานข้อมูลจะถูกบันทึกลงใน `wf.ActivityAuditLog` พร้อมระบุ User ID, IP Address, วันเวลา, และ Digest ของข้อมูลที่ถูกเปลี่ยน
