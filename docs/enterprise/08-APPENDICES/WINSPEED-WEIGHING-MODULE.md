# โมดูลชั่งของ WINSpeed — `WGHD` / `WGDT` / `WGDTReport`

เจ้าของระบบยืนยันว่า **สามตารางนี้ไม่ได้ย้ายข้อมูลมาจาก TruckScale** แต่เป็นของที่
พัฒนาขึ้นใหม่เพื่อมาแทน TruckScale จึงไม่ต้องเทียบจำนวนแถว

คำถามที่ต้องตอบคือ: **ถ้าบันทึกการชั่งลงที่นี่ WINSpeed จะปิด SO แล้ว Post Invoice ต่อได้ไหม
ส่วนนี้ใช้ยืนยันการชั่งเข้า–ออกได้หรือยัง**

ตรวจกับข้อมูลจริงบน Azure เมื่อ 31/08/2569 แล้ว

## ❌ คำตอบ: ตอนนี้ยังไม่ได้ — WGHD ไม่ได้ต่ออยู่กับสาย SO → Invoice เลย

**หลักฐานสามชั้น ตรงกันทั้งหมด**

### 1. ไม่มีอะไรในฐานอ้างถึง WG* เลย

| ตรวจ | ผล |
|---|---|
| คอลัมน์ชื่อ `WGHDId` / `WGDTId` นอกกลุ่ม WG* | **ไม่มีสักคอลัมน์** |
| foreign key เข้าหรือออกจาก WG* | **ไม่มีสักตัว** |

`SOHD` · `SODT` · `SOInvHD` ไม่รู้จักตารางชั่งเลยแม้แต่ทางเดียว

### 2. มี WGHD หรือไม่มี ใบส่งขายก็อยู่สถานะเดียวกันเป๊ะ

ใบส่งขาย (104) ทั้งหมดในช่วง พ.ค.–มิ.ย. 2569:

| กลุ่ม | `AppvFlag` | `CouponFlag` | จำนวนใบ |
|---|---|---|---|
| **มี** WGHD | `W` | `Y` | 86 |
| **ไม่มี** WGHD | `W` | `Y` | 1,348 |

ไม่ต่างกันแม้แต่ใบเดียว — ถ้า WGHD เป็นเงื่อนไขของการอนุมัติหรือการออกตั๋ว
สองกลุ่มนี้ต้องต่างกัน แต่ไม่ต่าง แปลว่า **WINSpeed ไม่ได้อ่าน WGHD เพื่อตัดสินอะไรเลย**

### 3. ใบที่ชั่งครบแล้วก็ไม่ได้ไปไกลกว่าใบอื่น

ใบที่มีน้ำหนักสุทธิครบ (4 ใบที่จับคู่ SO ได้) อยู่สถานะเดียวกับใบที่ไม่เคยชั่ง:
`103` → `AppvFlag='Y'` · `104` → `AppvFlag='W'`, `CouponFlag='Y'`

การชั่งเสร็จไม่ได้ทำให้ใบขยับ

## สรุปสำหรับการตัดสินใจ

**WGHD/WGDT วันนี้เป็นบันทึกคู่ขนาน ไม่ใช่ส่วนหนึ่งของสายเอกสาร**
บันทึกลงไปแล้วไม่มีผลต่อการปิด SO หรือการ Post Invoice เพราะไม่มีการเชื่อมต่อใด ๆ อยู่เลย

ถ้าต้องการให้ใช้ยืนยันการชั่งเข้า–ออกได้จริง ต้อง**สร้างการเชื่อมนั้นขึ้นมาก่อน** ซึ่งมีสองทาง

| ทาง | ใครทำ | ข้อสังเกต |
|---|---|---|
| ให้ Prosoft ต่อในตัว WINSpeed | Prosoft | ตรงที่สุด แต่ต้องรอผู้ขาย และเราคุมกำหนดเวลาไม่ได้ |
| เราต่อเองผ่าน schema `wf` | ทีมเรา | ทำได้ตาม ADR-003 (ไม่แตะ `dbo`) แต่ต้องระวังชนกับของที่ Prosoft จะทำภายหลัง |

**คำถามที่ต้องถามโรงงาน/Prosoft ก่อนเลือก:** โมดูลนี้ออกแบบมาให้ต่อกับ SO อยู่แล้วหรือยัง
ถ้าใช่ ทำไมยังไม่ต่อ — ถ้าไม่ใช่ แผนเดิมของผู้พัฒนาคืออะไร

## 🔴 อีกเรื่องที่ต้องแก้ก่อน: น้ำหนักไม่ไหลเข้ามาแล้วตั้งแต่ 28 พ.ค.

ต่อให้ต่อสาย SO เรียบร้อย ก็ยังยืนยันการชั่งไม่ได้ ถ้าไม่มีน้ำหนักให้ยืนยัน

| ตรวจ | ผล |
|---|---|
| แถวใน `WGHD` | 181 |
| มีน้ำหนักเข้า | 21 |
| มีน้ำหนักออก | 15 |
| **มีน้ำหนักสุทธิ** | **5** |
| **`CouponNo` ใน `WGDT`** | **0 / 311 — ว่างทั้งหมด** |

แยกตามช่วงเวลา:

| ช่วง | ลงทะเบียนรถ | ได้น้ำหนัก |
|---|---|---|
| 8–28 พ.ค. 2569 | 132 | 15 |
| **5–25 มิ.ย. 2569** | **49** | **0** |

หลัง 28 พ.ค. ไม่มีแถวไหนได้น้ำหนักเลย แต่คนหน้างานยังลงทะเบียนรถเข้ามาเรื่อย ๆ ถึง 25 มิ.ย.
แปลว่ายังมีคนใช้หน้าจอนี้อยู่ แต่ข้อมูลจากตาชั่งไม่ไหลกลับมาแล้ว และดูเหมือนยังไม่มีใครสังเกต
`UpdateBy` เป็น `NULL` ทั้ง 181 แถว — เขียนโดยกระบวนการอัตโนมัติ ไม่ใช่คนกรอก

**ต้องแจ้งโรงงานเรื่องนี้ ไม่ว่าจะตัดสินใจเรื่องอื่นอย่างไร**

## ✅ ของแถมจากการตรวจ ที่มีค่ากับงานอื่น

### 1. `EMSTOType` คือ taxonomy คลังเดียวกับที่รายงานเก่าใช้

`WGDT.STOCode` อ้าง `dbo.EMSTOType` ซึ่งให้ค่าตรงกับ `pd_pro_Godown` ใน MySQL **ทุกตัว**:

| `STOCode` | `EMSTOType` | `pd_pro_Godown` ใน MySQL |
|---|---|---|
| `สB` | สายพาน(B/B) | `สายพาน(B/B)` |
| `สH` | สายพาน(H/P) | `สายพาน(H/P)` |
| `คB` | คลัง(B/B) | `คลัง(B/B)` |
| `คH` | คลัง(H/P) | `คลัง(H/P)` |
| `03` `04` | โกดัง3 · โกดัง4 | `โกดัง3` · `โกดัง4` |

**ยืนยันข้อสรุปเรื่องรายงานจากแหล่งที่สองโดยอิสระ** — ตัวแยกว่าใบไหนเป็น `RptSaYPan`
หรือ `RptKlungSinKa` คือคลัง และ WINSpeed รู้จักคลังชุดเดียวกันนี้อยู่แล้วในชื่อ `EMSTOType`
ดู [TRUCKSCALE-REPORT-PLAN](TRUCKSCALE-REPORT-PLAN.md)

แปลว่ารายงานใบจ่ายสินค้า **ดึงคลังจาก WINSpeed ได้ ไม่ต้องพึ่ง MySQL**

### 2. ผูกกับใบสั่งขายจริง

`WGHD.DocuNo` ตรงกับ `SOHD` — เจอเป็นใบสั่งจอง (103) 124 ครั้ง และใบส่งขาย (104) 111 ครั้ง
(ตัวเลขรวมเกิน 181 เพราะ `DocuNo` ไม่ unique ข้าม `DocuType` ใบเดียวจึงตรงได้ทั้งสองชนิด
ตามสายเล่ม 103→104 ที่ยืนยันไว้แล้ว)

เป็นการจับคู่รถ↔ใบสั่งขายแบบเดียวกับที่ App ทำอยู่ แต่ทำในตัว WINSpeed เอง

## ข้อเสนอ

**ระยะสั้น — ไม่เปลี่ยนแหล่งข้อมูล** เดินหน้าย้าย TruckScale ไป Hostinger ตาม
[CUTOVER-to-hostinger](../../../deploy/truckscale-replica/CUTOVER-to-hostinger.md)
เพราะ `WGHD` ยังไม่ได้ต่อกับสาย SO และน้ำหนักยังไม่ไหล จึงยังพึ่งไม่ได้
ส่วนการย้ายฐานถอยกลับได้ ทำไปก่อนไม่เสียของ

**ระยะยาว — ปลายทางควรเป็น `WGHD`/`WGDT` ตามที่ตั้งใจไว้**
โมดูลนี้อยู่ใน WINSpeed อยู่แล้ว มีช่อง `CouponNo` ในตัว และใช้ `EMSTOType` ร่วมกับระบบอื่น
ต้องทำสองอย่างถึงจะแทน TruckScale ได้จริง: **ซ่อมให้น้ำหนักไหลเข้ามา** และ
**ต่อให้สาย SO อ่านมันจริง** ทำครบสองข้อแล้วจะเลิกใช้ TruckScale ได้ทั้งระบบ
ซึ่งดีกว่าการยกฐาน TruckScale ขึ้นคลาวด์แล้วใช้ต่อไปอีกสิบปี

**คำถามที่ต้องถามโรงงานก่อนตัดสินระยะยาว**

1. ใครเปิดใช้โมดูลนี้เมื่อ พ.ค. และตั้งใจให้มันแทน TruckScale หรือใช้คู่กัน
2. ตัวป้อนน้ำหนักที่หยุดไปเมื่อ 28 พ.ค. เป็นของ Prosoft หรือเขียนเอง
3. ถ้าซ่อมให้ไหลได้ จะยอมย้ายไปใช้เต็มตัวไหม — เพราะถ้ายอม แผนย้ายฐานขึ้นคลาวด์
   จะกลายเป็นงานชั่วคราวที่ไม่ต้องลงแรงมาก
