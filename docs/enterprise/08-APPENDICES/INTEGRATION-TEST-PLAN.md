# แผนทดสอบการเชื่อมต่อกับ WINSpeed (ฉบับแก้ลำดับ)

ฉบับ v1 วางลำดับผิดสองจุด เอกสารนี้แก้ให้ตรงกับสายเอกสารจริงที่วัดได้จากฐานข้อมูล

## สายเอกสารจริง

```
ใบเสนอราคา 102 ──► อนุมัติใบเสนอราคา 113
        │
        ▼
   ใบจอง 103 ──► อนุมัติใบสั่งจอง 119 (AIyy-00000)
        │
        ▼
  ใบส่งของ 104 (Kyy / Iyy)
        │
        ├── CouponFlag='Y' ──► ตั๋วปุ๋ย D69xxxxx  +  ใบแจ้งหนี้ 202 (เลขเดียวกับใบส่งของ)
        │                          │                        │
        │                          ▼                        ▼
        │                   ใบตัดตั๋วปุ๋ย 116            ใบรับชำระ 206
        │                   (รวมตามทะเบียนรถ)          (RVyy + RExy)
        │                          │
        │                          ▼
        │                   Post Invoice (WF) ──► ใบแจ้งหนี้ 107 (Jyy / Nyy)
        │
        └── CouponFlag='N' ──► ทางตัน ไม่มีใบแจ้งหนี้
```

## สองจุดที่ v1 ผิด

**1. ใบแจ้งหนี้ไม่ได้มาจากเมนู Credit Sale**
v1 ระบุว่าออกใบแจ้งหนี้จากเมนู Credit Sale ซึ่งได้ใบ 107 ชุด J/N
ความจริงคือใบที่ลูกค้าชำระคือ **202 ที่เกิดพร้อมใบส่งของและใช้เลขเดียวกัน**
วัดปี 2569: ใบรับชำระอ้างใบ 202 จำนวน 4,321 บรรทัด และอ้างใบ 107 **ศูนย์บรรทัด**
เมนู Credit Sale เป็นเส้นทางคู่ขนาน ไม่ใช่ทางหลักของงานนี้

**2. ชั่งออกไม่ใช่ขั้นตอนหลังใบส่งของ และไม่ใช่เงื่อนไขของตั๋วปุ๋ย**
เจ้าของระบบระบุว่าน้ำหนักต้องยืนยันบนใบส่งของ แต่ข้อมูลไม่สนับสนุนว่าชั่งออกมาก่อน
(ก.พ.–เม.ย. 2569: ระดับวัน วันเดียวกัน 57 · ชั่งทีหลัง 9 · ชั่งก่อน 0 —
ระดับเวลา ชั่งออกก่อน 55 · บันทึกใบก่อน 40) ส่วน **ชั่งเข้า มาก่อนเสมอ**
และคิวชั่งของ WINSpeed (`dbo.WGHD`) ผูกกับ **ใบจอง 103** ไม่ใช่ใบส่งของ
โดยไม่มีใบส่งของสักใบใน 61,852 ใบที่มีคิวชั่ง

## ลำดับทดสอบ

| ช่วง | สิ่งที่ทำ | ตรวจอะไร | สถานะ |
|---|---|---|---|
| 1 | สร้างใบเสนอราคาจากแอป → อนุมัติ | 102 → 113 · เลขชุด QU / QC | ✅ ผ่าน |
| 2 | ยืนยันเป็นใบจอง → อนุมัติใน WINSpeed | 103 · `CheckAll='Y'` · เข้าคิวอนุมัติ · ได้ AIyy | ✅ ผ่าน |
| 3 | ออกใบส่งของจาก Sale Order (WF) | 104 · `RefSOID` · `Refno=AIyy` · `RemaQty` ลด · SMAudit 2098003049 | ✅ ผ่าน |
| 4 | ตรวจตั๋วปุ๋ยและใบแจ้งหนี้ 202 | `CouponFlag='Y'` · `CouponNo` มีเลข · เกิดใบ 202 | ⛔ **ติด** — ดู [COUPON-FLAG-EVIDENCE](COUPON-FLAG-EVIDENCE.md) |
| 5 | ใบตัดตั๋วปุ๋ย 116 | รวมตั๋วตามทะเบียนรถ · `movebill` ตรงกับตาชั่ง | ⏸ รอช่วง 4 |
| 6 | Post Invoice (WF) → ใบ 107 | `WFRedemtionDT.SOInvID` · `PostInv='Y'` | ⏸ รอช่วง 4 |
| 7 | รับชำระ 206 | `ARReceDT.SOInvID` ชี้ใบ 202 · เลขชุด RVyy + RExy | ⏸ รอช่วง 4 |
| 8 | ตั๋วคุม | ใบจอง 103 ที่ `TransRegistration='ตั๋วคุม'` · ทยอยตัด `RemaQty` ที่ราคาล็อก | ยังไม่เริ่ม |
| 9 | Sale Trip | รถคันเดียว วันเดียว ลูกค้าหลายราย · รวมที่ใบตัดตั๋วตาม `CarLicense` | ยังไม่เริ่ม |
| 10 | รีเบท | สะสมจากตันที่ส่งจริง · เบิกตามแผน | ยังไม่เริ่ม |

## สิ่งที่ต้องเตรียมก่อนทดสอบ

1. **ตรวจตัวนับเลขที่เอกสาร** — `node scripts/audit-docuno-counters.js`
   ตัวนับที่ล้าหลังทำให้บันทึกไม่ผ่านเพราะออกเลขซ้ำ และไม่มีสัญญาณใดจนกดบันทึก
   แก้แล้วต้องปิด/เปิดหน้าจอนั้นใหม่ เพราะโปรแกรมจำเลขไว้ตั้งแต่เปิดฟอร์ม
2. **ตรวจทะเบียนพนักงานขาย** — ผู้เปิดใบต้องมี `EmpId` ที่อยู่ใน `dbo.EMSales`
   ไม่งั้น WINSpeed ปฏิเสธตอนอนุมัติด้วย "Salesman is not vaid!"
   ดูได้จาก `wf.v_SalesmanStatus` และแอปเตือนให้ตั้งแต่ตอนเปิดใบแล้ว
3. **ช่วงเวลาที่ข้อมูลสองฐานทับกัน** — สำเนา TruckScale หยุดที่ เม.ย. 2569
   ส่วน WINSpeed มีถึง ก.ค. 2569 · การ join นอกช่วงจะได้ศูนย์และดูเหมือนตัวเชื่อมพัง
