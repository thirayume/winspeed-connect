# ใบส่งของไม่ออกตั๋วปุ๋ย — สรุปหลักฐานสำหรับสอบถาม Prosoft

เอกสารนี้รวบรวมสิ่งที่วัดได้จากฐานข้อมูลจริง เพื่อใช้ตั้งคำถามกับผู้พัฒนา WINSpeed
ทุกตัวเลขในเอกสารนี้มาจากการนับในฐาน `dbwins_worldfert9` เมื่อ 19–20 สิงหาคม 2569

## อาการ

เมื่อบันทึกใบส่งของ (Sale Order → DocuType 104) โปรแกรมขึ้นคำเตือน

> รายการนี้เป็นรายการที่ไม่ออกตั๋วปุ๋ย ต้องการบันทึกหรือไม่ ?

เมื่อกดบันทึกต่อ ใบถูกสร้างขึ้นจริง แต่ **ไม่เกิดสามอย่างที่ควรเกิด**

1. ตั๋วปุ๋ยไม่ได้เลข — `dbo.WFCoupon` มีแถวเกิดขึ้น แต่ `CouponNo` ว่าง
   `ContainQty` = 0 และ `SackQty` = 0 (ปกติคือ `D69xxxxx`, 50 และ ตัน × 20)
2. `dbo.SOHD.CouponFlag` = `'N'` แทนที่จะเป็น `'Y'`
3. **ไม่มีใบแจ้งหนี้ `SOInvHD` DocuType 202 เกิดขึ้น** ทั้งที่ปกติจะเกิดพร้อมกัน

ผลคือเอกสารกลายเป็นทางตัน — ไม่มีใบแจ้งหนี้ จึงรับชำระไม่ได้ และเบิกรีเบทไม่ได้

## หลักฐานที่ 1 — เป็นสวิตช์เดียว แยกขาดสมบูรณ์

นับใบส่งของทั้งตาราง 61,852 ใบ

| `SOHD.CouponFlag` | มีใบแจ้งหนี้ 202 เลขเดียวกัน | จำนวน |
|---|---|---|
| `'Y'` | มี | **61,847 (ทุกใบ)** |
| `'N'` | ไม่มี | **5 (ทุกใบ)** |

ไม่มีข้อยกเว้นแม้แต่ใบเดียวทั้งสองฝั่ง

ใบแจ้งหนี้ 202 ปี 2569 ทั้ง 4,075 ใบ ใช้ `DocuNo` เดียวกับใบส่งของ และ `DocuDate`
ห่างกัน **0 วันทุกใบ** — ยืนยันว่าเกิดในจังหวะเดียวกับการบันทึกใบส่งของ ไม่ใช่ขั้นตอนแยก

## หลักฐานที่ 2 — หยุดทำงานหลัง 30 มิถุนายน 2569

ใบส่งของทุกใบถึง 30/06/2569 ออกตั๋วมีเลขครบ หลังจากนั้นไม่มีใบไหนออกได้อีกเลย
ตัวนับ `dbo.EMRunBrch` RunCode `couponno` ค้างที่ `D6903750` ไม่ขยับ

ห้าใบที่ `CouponFlag='N'` คือ

|---|---|---|
| `I64-03026` | 17/07/2564 | ใบเดียวในอดีต |
| `K69-01850` | 13/08/2569 | สร้างระหว่างทดสอบ |
| `K69-01851` | 19/08/2569 | สร้างระหว่างทดสอบ |
| `K69-01852` | 19/08/2569 | สร้างระหว่างทดสอบ |
| `K69-01853` | 19/08/2569 | สร้างระหว่างทดสอบ |

## หลักฐานที่ 3 — ไม่ได้เกิดจากระบบภายนอกที่ต่อเข้ามา

`K69-01853` สร้างจากใบจอง `I69-02069` ซึ่ง **WINSpeed สร้างเองทั้งใบ** เมื่อ 05/06/2569
(ลูกค้า 1078 · สินค้า `7-18040500BBCAR` 18-4-5 ตรารถเกษตร ซึ่งเคยออกตั๋ว `D6903748` มาแล้ว)
ทำผ่านหน้าจอ Sale Order ตามปกติทุกขั้นตอน — **ได้ผลเหมือนกันทุกประการ**

จึงไม่ใช่ผลจากข้อมูลที่ระบบอื่นเขียนเข้ามา

## หลักฐานที่ 4 — ใบที่ออกตั๋วสำเร็จ บันทึกโดยผู้ใช้คนละคนกับของเรา

นับการใช้หน้าจอ Sale Order (WF) จาก `dbo.SMAudit` หน้าจอ `2098003049`

| ผู้ใช้ | เครื่อง | จำนวนครั้ง | ล่าสุด |
|---|---|---|---|
| `USER-A` | `WF-PC-031` | 29,638 | 02/06/2568 |
| `USER-A` | `WF-PC-A` | 9,419 | 01/07/2569 |
| `USER-C` | `WF-PC-026` | 1,554 | 27/06/2565 |
| `USER-D` | `USER-023-PC` | 54 | 04/08/2566 |
| **`USER-B`** | **`WF-TEST-1`** | **2** | **19/08/2569** |
| **`USER-B`** | **`WF-TEST-2`** | **2** | **19/08/2569** |

การบันทึกใบส่งของในงานจริงทำโดย `USER-A` แทบทั้งหมด ส่วนสี่ใบที่ล้มเหลวบันทึกโดยบัญชี `USER-B`
ซึ่ง**ไม่เคยบันทึกใบส่งของสำเร็จมาก่อนเลย**

ตรวจ `dbo.security_info` หน้าจอ `w_sosaleorder_wf` แล้ว **ไม่พบสิทธิ์ระดับปุ่มที่ต่างกัน**
(มีเพียง `USER-C` ที่ถูกปิด new/edit/save) กลุ่มของผู้ใช้ต่างกันคือ
`USER-A` อยู่กลุ่ม `Sale Dept` อย่างเดียว ส่วน `USER-B` อยู่ทั้ง `Sale Dept` · `Accounting Dept` ·
`Cost&Inventory` · `Finance Dept`

## หลักฐานที่ 5 — ไม่ใช่เรื่องสิทธิ์ผู้ใช้ แต่แยกขาดตาม "เครื่อง"

ตรวจสิทธิ์สองบัญชีจากฐานข้อมูลตรง ๆ (`dbo.security_info`) โดยไม่ต้องเข้าระบบเป็นใคร

- หน้าจอ Sale Order (WF) / `w_sosaleorder_wf` — **สิทธิ์ระดับปุ่มเหมือนกันทุกอย่าง**
- ถ้าเทียบทั้งบัญชี **`USER-B` มีสิทธิ์มากกว่า `USER-A`** (เปิดทุกโมดูลในระบบ) ไม่ใช่น้อยกว่า
- ไม่พบธงตั้งค่าเรื่องตั๋วปุ๋ยใน `SOOption` / `ICOption` / `EMOptionExt` เลย

**สิทธิ์จึงอธิบายไม่ได้** แต่พอไล่ตาม "เครื่องที่บันทึก" (จาก `SMAudit` หน้าจอ 2098003049)
กลับแยกขาดสมบูรณ์ — ใบส่งของปี 2569 ที่ระบุเครื่องได้

| เครื่อง | CouponFlag | จำนวน |
|---|---|---|
| `WF-PC-A` (เครื่องผลิตจริง) | `Y` | 12 |
| `WF-NB-A` (เครื่องผลิตจริง) | `Y` | 1 |
| `WF-TEST-1` (เครื่องที่เราทดสอบ) | `N` | 2 |
| `WF-TEST-2` (เครื่องที่เราทดสอบ) | `N` | 2 |

รวมกับหลักฐานที่ 2 (หยุดหลัง 30/06/2569 ซึ่งเป็นวันสุดท้ายที่เครื่องผลิตจริงยังทำงาน)
ภาพจึงเปลี่ยนเป็น: **การออกตั๋วปุ๋ยเป็นความสามารถของเครื่องลูกข่าย ไม่ใช่ของข้อมูลหรือสิทธิ์ผู้ใช้**

เครื่องผลิตจริง (`WF-PC-031`, `WF-PC-A` ฯลฯ) น่าจะมีส่วนประกอบฝั่งไคลเอนต์ที่เครื่องเราไม่มี
เช่น ฟอร์ม/รายงานพิมพ์ตั๋วที่ติดตั้งเฉพาะเครื่อง หรือการตั้งค่าที่เก็บนอกฐานข้อมูล
ซึ่ง**อยู่นอกสิ่งที่แอปหรือฐานข้อมูลควบคุมหรือแก้ได้**

### ผลการทดลองแบบคุมตัวแปร — ยืนยันว่า "ไม่ใช่เรื่องผู้ใช้"

20/08/2569 เจ้าของระบบ login เป็น `USER-A` เอง (เพื่อรักษา audit trail ให้จริง) แล้วบันทึกใบส่งของ
**K69-01854** จากใบจอง `AI69-04539` **บนเครื่อง `WF-TEST-1` เครื่องเดียวกับที่ `USER-B` เคยทำ**

- คำเตือน "รายการนี้เป็นรายการที่ไม่ออกตั๋วปุ๋ย" **ขึ้นเหมือนเดิม**
- `CouponFlag = 'N'` · คูปองเกิดแต่ `CouponNo` ว่าง `ContainQty=0` `SackQty=0` — เหมือน `USER-B` ทุกอย่าง
- SMAudit ยืนยัน: `audit_username='USER-A'` · `audit_computername='WF-TEST-1'`

**เครื่องเดียวกัน เปลี่ยนแค่ผู้ใช้ → ผลเหมือนเดิม** จึง**ตัดสมมติฐานเรื่องบัญชีผู้ใช้/สิทธิ์ออกได้เด็ดขาด**
เหลือความเป็นไปได้ที่แยกไม่ออกด้วยข้อมูลชุดนี้สองทาง (ทั้งสองอยู่นอกแอปและฐานข้อมูล):
1. **การตั้งค่าเฉพาะเครื่อง** — เครื่องผลิตจริงมีส่วนประกอบที่เครื่องเราไม่มี
2. **การเปลี่ยนแปลงตามเวลา** — บางอย่างหยุดทำงานทั้งระบบหลัง 30/06/2569

### วิธีทดสอบที่จะแยกสองข้อสุดท้าย

บันทึกใบส่งของหนึ่งใบ **บนเครื่องผลิตจริงที่ตั้งค่าครบ** (เช่น `WF-PC-A`)

- ได้ `CouponFlag='Y'` → เป็นการตั้งค่าเครื่องลูกข่าย แก้ได้เองที่เครื่อง
- ได้ `'N'` เหมือนกัน → เป็นการเปลี่ยนแปลงระดับระบบตามเวลา ส่งเอกสารนี้ให้ Prosoft

> ข้อควรระวังตอนอ่าน `SMAudit`: `audit_docuno` เก็บแต่เลขที่เอกสาร ไม่มีชนิดเอกสาร
> และเลขเดียวกันใช้ได้ทั้งใบจอง 103 และใบส่งของ 104 การกรองด้วยเลขอย่างเดียว
> จึงดึงรอยของอีกเอกสารติดมาด้วย ต้องดูที่ `audit_screen` ประกอบเสมอ

## สิ่งที่ตรวจแล้วและตัดออกได้

ทุกข้อตรวจด้วยการนับจากฐาน ไม่ใช่การอนุมาน

| ตรวจอะไร | ผล |
|---|---|
| `EMGood.CouponType` | `'N'` ทั้ง 544 รายการ รวมสินค้าที่เคยออกตั๋วจริง — ไม่ใช่ตัวแยก |
| กลุ่มสินค้า `GoodGroupID` | กลุ่มที่เคยออกตั๋วมีทั้ง 1003 และ 1004 — ไม่ใช่ตัวแยก |
| หน่วยนับ `EMGoodMultiUnit` | สินค้าที่ออกตั๋วได้กับไม่ได้ ตั้งหน่วยเหมือนกันทุกช่อง |
| `SODT.GoodStockRate1` | ใบจอง 103 ทั้ง 113,585 บรรทัดเป็น 0 เหมือนกันหมด |
| `SODT.CouponType` | ว่างทั้งใบที่ออกตั๋วได้และไม่ได้ |
| `SOHD.SaleAreaID` / `DeptID` | ใบที่ออกตั๋วได้ 994 ใบมีทั้งสองช่องว่าง |
| แฟ้มลูกค้า `EMCust` | ไม่มีคอลัมน์ใดเกี่ยวกับตั๋วปุ๋ย |

| คิวชั่ง `dbo.WGHD` | 181 แถว ทั้งหมดชี้ใบจอง 103 · **ไม่มีใบส่งของสักใบที่มีคิวชั่ง** |
| ตาชั่ง TruckScale (MySQL) | WINSpeed อ่านฐาน MySQL ไม่ได้ จึงมีผลไม่ได้ |

## คำถามถึง Prosoft

หลักฐานชี้ว่าน่าจะเป็น**การตั้งค่าฝั่งเครื่องลูกข่าย** (ดูหลักฐานที่ 5) จึงถามเจาะไปทางนั้น

1. การออกตั๋วปุ๋ยตอนบันทึกใบส่งของ ขึ้นกับส่วนประกอบหรือการตั้งค่าใดที่ติดตั้ง**เฉพาะเครื่อง**
   (ฟอร์มพิมพ์ตั๋ว / รายงาน / ค่าใน registry / ไฟล์ตั้งค่าเครื่อง)
2. ถ้าไม่ใช่เรื่องเครื่อง เงื่อนไขนั้นเก็บที่ตาราง/คอลัมน์ใดในฐานข้อมูล (เราตรวจ `EMGood.CouponType`,
   กลุ่มสินค้า, หน่วยนับ, `SaleAreaID`, `DeptID`, `SODT.CouponType`, `SOOption`, `ICOption`,
   คิวชั่ง `WGHD` และสิทธิ์ผู้ใช้แล้ว — ไม่พบตัวแยก)
3. มีอะไรทำให้ความสามารถนี้หยุดหลัง 30/06/2569 หรือไม่ (ตรงกับวันสุดท้ายที่เครื่องผลิตจริงทำงาน)
4. เมื่อ `CouponFlag = 'N'` แล้ว มีวิธีแก้ใบที่ออกไปแล้วให้กลับมาออกตั๋วและออกใบแจ้งหนี้ 202 ได้หรือไม่

## ข้อมูลอ้างอิงสำหรับตรวจสอบซ้ำ

```sql
-- หลักฐานที่ 1
SELECT RTRIM(h.CouponFlag) AS CouponFlag,
       CASE WHEN i.SOInvID IS NULL THEN 'no 202' ELSE 'has 202' END AS Inv,
       COUNT(*) AS n
FROM dbo.SOHD h
LEFT JOIN dbo.SOInvHD i ON i.Docutype = '202' AND RTRIM(i.DocuNo) = RTRIM(h.DocuNo)
WHERE h.DocuType = '104'
GROUP BY RTRIM(h.CouponFlag), CASE WHEN i.SOInvID IS NULL THEN 'no 202' ELSE 'has 202' END;

-- หลักฐานที่ 2
SELECT RTRIM(DocuNo), CONVERT(varchar(10), DocuDate, 120)
FROM dbo.SOHD WHERE DocuType = '104' AND RTRIM(CouponFlag) = 'N';
```
