## SOP-01 — กระบวนการใบสั่งขาย

**วัตถุประสงค์** ให้ทุกใบสั่งขายมีหลักฐานครบทุกการเปลี่ยนสถานะ และสืบย้อนไปถึงเอกสารใน WINSpeed ได้เสมอ

### 1.2 ขั้นตอนปฏิบัติ

1. **สร้างร่าง** — หน้าขาย (POS) เลือกลูกค้า สินค้า ปริมาณ ราคา
   ระบุ**ทะเบียนรถ** หรือทำเครื่องหมาย "ไม่ใช้รถ" — ข้ามไม่ได้
2. **ตรวจซ้ำ** — Counter-Sales กดปุ่ม "ตรวจแล้ว" · ระบบบันทึก `wf.SalesOrder.VerifiedAt`
   🔄 **ไม่ตรวจซ้ำ = ยืนยันไม่ได้** (FR-022 · `ADMIN` ข้ามได้)
3. **ยืนยัน** — ระบบเรียก `wf.sp_ConfirmSalesOrder` สร้างใบสั่งจอง 103 ใน WINSpeed
4. **อนุมัติ** — ผู้มีอำนาจอนุมัติใน**หน้าจอ WINSpeed** (`อนุมัติใบสั่งจอง (WF)`) จนได้เลข `AIyy-00000`
5. **จัดสินค้า → ขึ้นรถ → ชั่งออก** — ดู SOP-03

## SOP-03 — การชั่งออกและส่งสินค้า 🔄

**วัตถุประสงค์** ให้ทุกใบที่ออกจากโรงงานมีหลักฐานน้ำหนักที่ตรวจสอบได้ และยอดตรงกับที่คีย์ไว้

### 3.1 เงื่อนไขก่อนเริ่ม

ใบสั่งขายต้องอยู่สถานะ `LOADED` เท่านั้น

### 3.2 ขั้นตอนปฏิบัติ

1. รถขึ้นชั่ง — บันทึก **น้ำหนักชั่งออก (gross)** และ **น้ำหนักรถเปล่า (tare)**
2. ระบุเลขเครื่องชั่ง และเลขเที่ยว (movebill) ถ้ามี
3. กด "ชั่งออก" — ระบบคำนวณสุทธิ = gross − tare แล้วเทียบกับยอดที่คีย์ไว้
4. ถ้าอยู่นอกพิกัด ต้องกรอก**เหตุผล** และระบุ**ผู้อนุมัติ** พร้อมแนบ**ภาพหลักฐาน**

### 3.3 🔄 ด่านที่ระบบบังคับ (เดิมไม่มีเลย)

| # | เงื่อนไข | ข้อความ |
|---|---|---|
| 1 | ต้องมีทั้ง gross และ tare | *ต้องระบุน้ำหนักชั่งออก (weighOutWeight) และน้ำหนักรถเปล่า (tareKg)* |
| 2 | gross > 0 และ tare ≥ 0 | *น้ำหนักต้องเป็นค่าบวก* |
| 3 | สุทธิ > 0 | *น้ำหนักสุทธิต้องมากกว่า 0 (ชั่งออก {g} − รถเปล่า {t} = {net})* |

> **ทำไมต้องบังคับ** — เดิมส่งของได้โดยไม่มีน้ำหนักเลย แล้วระบบตั้ง `clearflag='Y'` ใน WINSpeed ทันที
> ได้ใบสั่งขายสถานะ `SHIPPED` ที่ไม่มีหลักฐานน้ำหนักใด ๆ ซึ่งใช้เป็นหลักฐาน ISO ไม่ได้

### 3.4 สิ่งที่ระบบบันทึกทุกครั้งที่ชั่งออก

| ปลายทาง | เก็บอะไร |
|---|---|
| `wf.SalesOrderExt.WeighOutWeight` | น้ำหนักชั่งออก |
| `wf.WeighTicket` | gross · tare · net · เลขเครื่องชั่ง · movebill · น้ำหนักที่คาด · ผลต่าง (kg / %) · สถานะพิกัด · เหตุผล/ผู้อนุมัติ/ภาพหลักฐาน |
| MySQL `db_truckscale` | write-back ใบชั่งและบรรทัดสินค้า (`tblproduct_detail`) |
| `wf.RebateLedger` | ตั้ง accrual รีเบทให้เจ้าของใบสั่งขาย |
| `dbo.SMAudit` screen `990000004` | รอยการชั่งออกฝั่ง WINSpeed |
| `wf.OutboxEvent` | `SO_SHIPPED` และ `TRUCKSCALE_WRITEBACK` (ถ้า write-back ล้ม จะ retry) |

> ⚠ **ระบบไม่ตั้ง `clearflag='Y'` ใน WINSpeed อีกแล้ว** เพราะทำให้เอกสารหายจากหน้าจอ Post Invoice
> ตอนนี้อาศัย `wf.SalesOrderExt.WeighOutWeight` อย่างเดียว

### 3.5 ถ้า write-back ไปเครื่องชั่งล้มเหลว

ระบบ **ไม่หยุดการส่งของ** แต่:
1. บันทึกผลลง `wf.WeighTicket` เพื่อให้รายงานกระทบยอด R-3 แยกได้ว่าใบไหน `inserted` / `updated` / ล้มเหลว
2. เข้าคิว `wf.OutboxEvent` ให้ worker ลองใหม่

ระบบ **ไม่ยิงคิวรีตอนแท็บเบราว์เซอร์ถูกซ่อน** — เปิดค้างไว้ทั้งวันได้โดยไม่ลากฐานผลิต

> แท็บสถานะสด **ไม่มีช่องเลือกวันที่โดยตั้งใจ** — รถที่ลงทะเบียนเมื่อวานแล้วยังชั่งไม่จบ
> ต้องยังอยู่ในคิววันนี้ ถ้ากรองด้วยวันที่รถกลุ่มนี้จะหายไปเงียบ ๆ ซึ่งอันตรายกว่าการแสดงเกิน

### 9.2 สถานะที่ต้องอ่านให้ถูก

| สถานะ | หมายความว่า | ต้องทำอะไร |
|---|---|---|
| **1 · รอเข้าชั่ง** | รถลงทะเบียนแล้ว ยังไม่ขึ้นตาชั่ง | รอ |
| **2 · ชั่งเข้าแล้ว** | มีน้ำหนักครั้งแรกแล้ว | รอโหลด/ลงสินค้าแล้วชั่งครั้งที่สอง |
| **3 · ชั่งออกแล้ว** | ชั่งครบสองครั้ง ได้น้ำหนักสุทธิ | **ถือว่าใบสั่งขายส่งของแล้ว (SHIPPED)** |

**ทิศทางน้ำหนักกลับกันระหว่างขายออกกับซื้อเข้า** — อ่านผิดจะสรุปน้ำหนักผิด

| ชนิด | รถขาเข้า | รถขาออก | น้ำหนักสินค้า |
|---|---|---|---|
| **ขายออก (SO)** | เปล่า | หนัก | ชั่งออก − ชั่งเข้า |
| **ซื้อเข้า (PO)** | หนัก | เปล่า | ชั่งเข้า − ชั่งออก |
| **ย้ายภายใน (MO)** | ตามงาน | ตามงาน | ใช้ค่าที่เครื่องชั่งบันทึก |

หน่วย: น้ำหนักเป็นกิโลกรัม · **1 กระสอบ = 50 กก.**

### 9.3 ⚠ ข้อจำกัดที่ต้องแจ้งผู้ใช้ทุกครั้ง

| # | ข้อเท็จจริง | ความหมายกับงานหน้างาน |
|---|---|---|
| 1 | **ข้อมูลชุดนี้ยังเป็นชุดทดสอบ** (เจ้าของระบบยืนยัน) | ยังใช้ตัดสินใจไม่ได้ |
| 2 | 181 ใบ · ได้น้ำหนักสุทธิจริงเพียง 5 ใบ · ชั่งออกครั้งล่าสุด 26 พ.ค. 2569 | หน้าจอจะว่างจนกว่าจะเริ่มชั่งจริง |
| 3 | `CouponNo` ว่างทั้ง 311 บรรทัด | ผูกใบชั่งกับตั๋วคุมยังทำไม่ได้ |
| 4 | **สถานะ 3 ไม่ได้เดินสถานะเอกสารใน `SOHD`** | "3 = SHIPPED" เป็นการตีความของแอป · สิ่งที่ปิด SO จริงยังคงเป็นการตัดตั๋วปุ๋ย |
| 5 | ใบที่ผิดปกติ 11 ใบ (สุทธิติดลบ · สุทธิเป็นศูนย์ทั้งที่ชั่งครบ · สูตรไม่ตรง) | ดูแท็บ "ผิดปกติ" ก่อนเชื่อยอดรวม |

### 9.4 คำถามที่ต้องตอบก่อนเปิดใช้จริง

**ต้องมีปุ่มกดยืนยัน 1 → 2 → 3 หรือไม่ — คำตอบคือ ไม่ควรมี**

1. เจ้าของระบบสั่งไว้ว่าสามตารางนี้เราจะไม่เขียน ปุ่มยืนยันต้องเขียน จึงขัดกับข้อกำหนด
2. `WGHD.UpdateBy` เป็น NULL ทุกแถว = เครื่องชั่งเขียนเองอัตโนมัติอยู่แล้ว ไม่ต้องมีคนกด
3. ถ้ามีทั้งเครื่องชั่งและปุ่มในแอปเดินสถานะเดียวกัน จะได้แหล่งความจริงสองแหล่งที่ขัดกันได้

**แต่ยังต้องมีจังหวะยืนยันฝั่งแอป** — เพราะ WINSpeed ไม่ปิด SO ให้ (ข้อ 4 ใน §9.3)
จังหวะนั้นคือ `PATCH /api/so/:id/ship` เดิม ซึ่งเขียนลง `wf` เท่านั้น ไม่แตะ WGxx
สิ่งที่ควรเปลี่ยนคือ **ให้ปุ่มนั้นดึงน้ำหนักจาก WGHD มาเติมให้ แทนที่จะให้คนคีย์เอง** — รอเจ้าของระบบตัดสิน
