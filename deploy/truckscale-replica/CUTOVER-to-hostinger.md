# ย้าย TruckScale ไป Hostinger — ขั้นตอนลงมือจริง

เจ้าของตัดสินแล้ว 31/08/2569: **ย้าย 100% ไปคลาวด์ที่ Hostinger เลิกใช้ MySQL โรงงาน**
เหตุผลและหลักฐานอยู่ใน [PLAN-move-to-cloud.md](PLAN-move-to-cloud.md) — ไฟล์นี้คือขั้นตอนลงมือ

## สิ่งที่พิสูจน์ไปแล้ว ไม่ต้องพิสูจน์ซ้ำ

- `WorldFerth.exe` ไม่มี host อยู่ในไบนารี → เปลี่ยน ODBC DSN อย่างเดียวก็ย้ายฐานได้
- ฐานคลาวด์รองรับคำสั่ง SQL ของโปรแกรมครบ **11/11** (`Test-TruckScaleCompat.ps1`)
- บัญชีจำกัดสิทธิ์ + REQUIRE SSL ใช้งานได้จริง `DROP DATABASE` ถูกบล็อก

## ⚠️ สามอย่างที่ยังไม่รู้ ต้องเก็บก่อนเริ่ม

| ไม่รู้ | ทำไมต้องรู้ | หาอย่างไร |
|---|---|---|
| **ที่อยู่ MySQL โรงงาน** | ต้องดัมป์ข้อมูลจากที่นั่น | รัน `Set-TruckScaleDSN.ps1 -TestOnly` บนเครื่องลูกข่ายสักเครื่อง |
| **จำนวนเครื่องลูกข่ายทั้งหมด** | ตกเครื่องเดียว = ข้อมูลแยกร่างทันที | เดินนับหน้างาน อย่าเดา |
| **IP สาธารณะของโรงงาน** | ใช้เปิดไฟร์วอลล์ให้ | เปิด `https://api.ipify.org` จากเครื่องในโรงงาน |

**ห้ามเริ่มขั้นที่ 3 จนกว่าจะครบทั้งสาม** — โดยเฉพาะจำนวนเครื่อง

## ขั้นตอน

### 1. เตรียมฐานปลายทาง (ไม่กระทบของเดิม ถอยได้ตลอด)

```bash
# บนเซิร์ฟเวอร์ Hostinger
# ก) เปิดไฟร์วอลล์ให้ IP โรงงาน
/opt/worldfert/app/deploy/cloud-vps/server/allowlist.sh add <ip-โรงงาน>

# ข) สร้างบัญชีที่โปรแกรมต้องใช้ (แก้ IP กับรหัสในไฟล์ก่อน)
docker exec -i wf-mysql mysql -uroot -p < Harden-CloudMySQL.sql
```

โรงงานเป็น IP ไม่คงที่ ให้ใช้ DDNS แล้วสั่ง
`allowlist.sh add-ddns <ชื่อโดเมน> && allowlist.sh install-timer`
จะตามให้เองทุก 5 นาที ไม่ต้องมาแก้มือทุกครั้งที่ ISP เปลี่ยน IP

### 2. ย้ายข้อมูล — **ทั้ง 22 ตาราง ไม่ใช่ 6**

`push-agent/` ส่งแค่ 6 ตาราง ซึ่งพอสำหรับทำรายงาน แต่**ไม่พอสำหรับย้ายทั้งระบบ**
โปรแกรมอ้างถึงอย่างน้อย 8 ตาราง และฐานจริงมี 22

```bash
# จากเครื่องในโรงงานที่ต่อ MySQL โรงงานได้
mysqldump -h <โฮสต์โรงงาน> -u root -p \
  --single-transaction --routines --triggers --events \
  --default-character-set=utf8 \
  db_truckscale > db_truckscale_cutover.sql
```

`--single-transaction` ทำให้ได้ภาพ ณ จุดเดียวโดยไม่ล็อกตาราง — เครื่องชั่งยังทำงานได้ระหว่างดัมป์

โหลดขึ้นคลาวด์แล้ว **นับแถวเทียบทุกตาราง** ก่อนไปขั้นถัดไป

```sql
SELECT TABLE_NAME, TABLE_ROWS FROM information_schema.TABLES
 WHERE TABLE_SCHEMA='db_truckscale' ORDER BY TABLE_NAME;
```

ตัวเลขอ้างอิงจากฐานคลาวด์ปัจจุบัน (31/08/2569): `tblproduct_detail` 541,716 ·
`tblscale` 408,501 · `tbl_keyone` 400,507 · `tbl_driver` 33,140 · `tblorder` 5,890 ·
`tblcustomer` 2,475 · `tblproduct` 491 — ที่เหลือเป็นตารางเล็ก

### 3. ตรวจก่อนแตะเครื่องลูกข่าย

```powershell
.\Test-TruckScaleCompat.ps1 -ExePath <path>\WorldFerth.exe `
  -ConnectionString "Driver={MySQL ODBC 8.0 Unicode Driver};SERVER=<โฮสต์คลาวด์};PORT=3306;DATABASE=db_truckscale;UID=<u>;PWD=<p>;CHARSET=utf8;SSLMODE=REQUIRED"
```

**ต้องผ่านทุกข้อ** ถ้ามีข้อไหนบอกว่าตารางหรือคอลัมน์ไม่มี แปลว่าย้ายข้อมูลไม่ครบ กลับไปขั้น 2

### 4. หยุดการชั่ง แล้วดัมป์รอบสุดท้าย

ระหว่างขั้น 2 ถึง 4 เครื่องชั่งยังเขียนลงฐานโรงงานอยู่ ต้องมีหน้าต่างหยุดสั้น ๆ

1. แจ้งหน้างานหยุดชั่ง
2. ดัมป์ซ้ำแบบขั้น 2 (รอบนี้ข้อมูลนิ่งแล้ว)
3. โหลดทับบนคลาวด์
4. นับแถวเทียบอีกครั้ง

> ทำขั้น 2 ไว้ก่อนเพื่อให้รอบนี้สั้นที่สุด ไม่ใช่ทำซ้ำเปล่า ๆ

### 5. สลับเครื่องลูกข่ายทีละเครื่อง

```powershell
# ทำเครื่องแรกเครื่องเดียวก่อน แล้วชั่งจริงหนึ่งคันดูให้ครบวงจร
.\Set-TruckScaleDSN.ps1 -Server <โฮสต์คลาวด์> -Scope Machine -ExePath <path>\WorldFerth.exe
```

เครื่องแรกต้องผ่านสามอย่างนี้ก่อนไปเครื่องที่สอง — เป็นสามอย่างที่ทดสอบด้วย SQL ไม่ได้:

1. เปิดโปรแกรมผ่าน (ฮาร์ดล็อก `libHardlock.dll` ไม่เกี่ยวกับฐาน แต่ถ้าไม่ผ่านก็ใช้ไม่ได้)
2. **พิมพ์รายงาน Crystal ออกมาได้จริง**
3. ชั่งเข้า-ออกครบหนึ่งคัน แล้วข้อมูลขึ้นบนคลาวด์ถูกต้อง

ผ่านแล้วค่อยไล่เครื่องที่เหลือ **ให้ครบทุกเครื่อง** เครื่องที่ตกจะยังเขียนลงฐานเก่าเงียบ ๆ

### 6. ปิดทางกลับของฐานเก่า

หลังสลับครบแล้ว **อย่าเพิ่งลบฐานโรงงาน** แต่ต้องทำให้เขียนไม่ได้
ไม่งั้นเครื่องที่ตกหล่นจะเขียนลงไปโดยไม่มีใครรู้

```sql
-- บน MySQL โรงงาน
SET GLOBAL read_only = ON;
SET GLOBAL super_read_only = ON;
```

เฝ้าหนึ่งสัปดาห์ ถ้าไม่มีอะไรพยายามเขียน แปลว่าไม่มีเครื่องตกหล่น ค่อยปลดเครื่องออก

## ถอยกลับ

| ถอยตอนไหน | ทำอย่างไร | เสียอะไร |
|---|---|---|
| ขั้น 1-3 | ไม่ต้องทำอะไร ยังไม่แตะของเดิมเลย | ไม่เสีย |
| ขั้น 5 (บางเครื่อง) | `Set-TruckScaleDSN.ps1 -Restore` บนเครื่องที่สลับไปแล้ว | ข้อมูลที่ชั่งบนคลาวด์ระหว่างนั้น ต้องคัดกลับเอง |
| ขั้น 6 แล้ว | ปลด `read_only` ที่โรงงาน แล้ว `-Restore` ทุกเครื่อง | ต้องย้ายข้อมูลจากคลาวด์กลับลงโรงงาน |

**ถอยยากขึ้นทุกขั้น** จุดที่ยังถอยฟรีคือก่อนขั้น 5 — ตรวจให้พอใจตรงนั้น

## เรื่องที่ยังไม่มีคำตอบ และไม่ควรข้าม

**เน็ตโรงงานล่มแล้วชั่งไม่ได้** เจ้าของยกข้อกังวลนี้ออกโดยตั้งใจ และรับความเสี่ยงแล้ว
แต่ "ตั้งใจให้เน็ตไม่ล่ม" ไม่ใช่แผนสำรอง ควรมีอย่างน้อยหนึ่งอย่าง:

- เน็ตเส้นที่สอง (4G/5G router สำรอง สลับอัตโนมัติ) — ถูกและได้ผลที่สุด
- หรือ MySQL ตัวเล็กที่โรงงานคอยรับแทนตอนคลาวด์ล่ม แล้วค่อยส่งตามทีหลัง
  (ซับซ้อนกว่ามาก และเป็นทาง ข. ที่เพิ่งตัดทิ้งไป)

ถ้าไม่ทำอะไรเลย ต้องรู้ตัวว่าเน็ตล่ม = รถเข้าคิวรอหน้าโรงงาน ชั่งไม่ได้สักคัน
