# ตัวผลักข้อมูล TruckScale ขึ้นคลาวด์

ทำงานที่เครื่องในโรงงาน อ่านจาก MySQL ตัวกลาง แล้วผลักขึ้นคลาวด์
**ต่อขาออกอย่างเดียวทั้งสองทาง · อ่านอย่างเดียวที่ต้นทาง**

## ทำไมไม่ใช้ replication ของ MySQL

| เรื่อง | replication | ตัวผลักนี้ |
|---|---|---|
| ทิศทางการต่อ | ปลายทางต่อ**เข้า**หาโรงงาน → ต้องมีอุโมงค์/เปิดพอร์ต | โรงงานต่อ**ออก** → ใช้เน็ตธรรมดา |
| แก้ config MySQL โรงงาน | ต้องเปิด binlog + ตั้ง server_id | **ไม่ต้องแตะ** |
| รีสตาร์ต MySQL โรงงาน | **ต้อง** = เครื่องชั่งทุกเครื่องหยุด | **ไม่ต้อง** |
| สิทธิ์ที่ต้องใช้ที่ต้นทาง | `REPLICATION SLAVE` | `SELECT` |
| ความหน่วง | ~วินาที | ตามรอบที่ตั้ง (ปริยาย 60 วินาที) |

ถ้ายอมรับความหน่วงระดับนาทีได้ ตัวผลักนี้แลกมาด้วยการไม่ต้องแตะระบบที่กำลังใช้งานอยู่เลย

## ติดตั้งและรัน

```bash
SRC_HOST=192.168.x.x  SRC_USER=readonly_user  SRC_PASS=***  SRC_DB=db_truckscale \
DST_HOST=<คลาวด์>     DST_USER=***           DST_PASS=***  DST_DB=db_truckscale \
INTERVAL_SEC=60 \
node sync-agent.js
```

`--once` = รอบเดียวจบ (ใช้ทดสอบหรือรันด้วย Task Scheduler)

| ตัวแปร | ปริยาย | ความหมาย |
|---|---|---|
| `INTERVAL_SEC` | 60 | เว้นระยะแต่ละรอบ |
| `BATCH` | 2000 | จำนวนแถวต่อคำสั่ง |
| `REFRESH_TAIL` | 2000 | ส่งซ้ำกี่แถวท้าย เพื่อจับการแก้ย้อนหลัง |
| `STATE_PATH` | `watermark.json` | ไฟล์จำตำแหน่ง |

### บัญชีที่ต้นทางควรเป็นแบบอ่านอย่างเดียว

```sql
CREATE USER 'ts_reader'@'%' IDENTIFIED BY '<รหัสที่แข็งแรง>';
GRANT SELECT ON db_truckscale.* TO 'ts_reader'@'%';
```

ตัวสคริปต์สั่ง `SET SESSION TRANSACTION READ ONLY` ไว้อีกชั้น แต่บัญชีที่จำกัดสิทธิ์คือด่านจริง
**อย่าใช้ `root` ตัวเดียวกับที่ TruckScale ใช้**

## ตารางที่ผลัก

รายงานต้นฉบับทั้ง 41 ใบใช้รวมกันเพียง 6 ตาราง (ดู `TRUCKSCALE-REPORT-INVENTORY`)
ตัวผลักจึงส่งครบทั้งหกให้พอสำหรับทำรายงานบนคลาวด์

| ตาราง | แถว (ณ 31/08/2569) | วิธีตาม |
|---|---|---|
| `tblscale` | 403,933 | PK เพิ่มขึ้น + ช่วงท้าย |
| `tblproduct_detail` | 550,216 | PK เพิ่มขึ้น + ช่วงท้าย |
| `tbl_keyone` | 407,991 | PK เพิ่มขึ้น + ช่วงท้าย |
| `tblcustomer` | 2,475 | PK เพิ่มขึ้น + ช่วงท้าย |
| `tblproduct` | 491 | PK เพิ่มขึ้น + ช่วงท้าย |
| `tbl_boat` | 8 | **ส่งทั้งตาราง** — `bo_id` ไม่ใช่ auto-increment |

## วิธีตามข้อมูล

ตารางที่โตเรื่อย ๆ มี PK เป็น auto-increment (`one_id` · `s_id` · `pd_id` · `id`)
ของใหม่จึงตามด้วย `PK > ค่าที่จำไว้` ได้ตรง ๆ

แต่ของเดิมถูกแก้ได้ — **ตั๋วถูกสร้างตอนชั่งเข้า แล้ว UPDATE ตอนชั่งออก**
ถ้าตามแค่ PK จะพลาดน้ำหนักออกทั้งหมด จึงส่งซ้ำช่วงท้าย `REFRESH_TAIL` แถวทุกรอบ
ปลายทางใช้ `INSERT ... ON DUPLICATE KEY UPDATE` ส่งซ้ำจึงไม่เสียหาย

ถ้าโรงงานชั่งหนักกว่า 2000 รายการต่อช่วงที่ตั๋วยังเปิดค้าง ให้เพิ่ม `REFRESH_TAIL`

## หาที่อยู่ MySQL ของโรงงาน

ที่อยู่ไม่ได้อยู่ในตัวโปรแกรม — อยู่ใน **ODBC DSN ของแต่ละเครื่อง client**
รันบนเครื่องที่มี TruckScale ติดตั้งอยู่:

```powershell
Get-ItemProperty 'HKLM:\SOFTWARE\WOW6432Node\ODBC\ODBC.INI\TruckScales' |
  Select-Object SERVER, PORT, DATABASE, DRIVER
```

ถ้าไม่พบ ให้ลอง `HKCU:\SOFTWARE\ODBC\ODBC.INI\TruckScales` และชื่อสำรอง `TruckScaleV5_Backup`
DSN เป็นแบบ 32-bit เพราะ `WorldFerth.exe` เป็น x86

## ให้รันตลอดเวลา

Windows — สร้าง Task Scheduler แบบ *At startup* + *Restart on failure*
หรือห่อด้วย [NSSM](https://nssm.cc/) ให้เป็น service

ตัวสคริปต์ปิดตัวเองอย่างเรียบร้อยเมื่อได้ SIGINT/SIGTERM และรอบไหนล้มก็ข้ามไปรอบหน้า
ไม่หยุดทั้งตัว

## ข้อจำกัดที่ต้องรู้

- **ลบแถวที่ต้นทางจะไม่ตามไปลบที่ปลายทาง** — ตัวผลักเห็นเฉพาะแถวที่ยังอยู่
  ถ้าจำเป็นต้องตรงกันเป๊ะ ต้องเทียบยอดเป็นรอบแยกต่างหาก
- ผลัก 6 ตารางจากทั้งหมด 22 ตารางในฐาน — พอสำหรับรายงานต้นฉบับทุกใบ
  ถ้าต้องการตารางอื่นให้เพิ่มใน `TABLES` ของสคริปต์
- ความหน่วงเท่ากับ `INTERVAL_SEC` ไม่ใช่เรียลไทม์
